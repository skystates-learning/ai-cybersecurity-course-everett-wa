Why AI and cybersecurity are now one conversation

Attackers use AI to write more convincing phishing, scout targets faster and speed up exploitation. At the same time, companies are rolling out chatbots, copilots and AI agents of their own, and every one of those is a new surface to protect. Security teams are being asked to do two jobs at once: use AI security tools to keep up with the volume of alerts, and make sure the AI the business adopts does not become the weak link.

That is why a modern program covers both sides. On the defense side you work with AI-driven threat detection, machine learning for cybersecurity and generative AI in cybersecurity to read logs, summarize incidents and enrich indicators. On the protection side you study LLM and application security: how models get attacked, and what guardrails actually help.

From concepts to one working project

Most articles explain RAG, agents and LLM security as separate topics. In practice they meet in a single pipeline, and that is the idea behind the program's project-based approach. Here is the shape of one small project: an alert comes in, a guard checks it for prompt injection, retrieval pulls in relevant threat context, and the workflow either gives a verdict or hands it to a human analyst.

[Incoming alert] │ ▼ [1. Guard: screen the text for prompt injection] ├── Suspicious ➔ [Escalate to a human analyst] ▼ [2. Retrieve: look up threat intelligence (RAG)] │ ▼ [3. Triage: produce a verdict and severity] │ ▼ [4. Human-in-the-loop for high severity ➔ Done]

This skeleton uses LangGraph and plain Python so you can see the structure. In a real build, retrieve would query a vector database and triage would call a model; the keyword guard is only a starting point, and layered defenses go further.

from typing import TypedDict, List
from langgraph.graph import StateGraph, END

class AlertState(TypedDict):
    alert: str
    safe: bool
    context: List[str]
    verdict: str
    needs_human: bool

SUSPICIOUS = ["ignore previous instructions", "reveal your system prompt"]

# Stand-in for a vector database lookup over threat intelligence
THREAT_INTEL = {
    "powershell": "ATT&CK T1059.001: PowerShell command execution",
    "failed login": "ATT&CK T1110: Brute force",
}

def guard(state: AlertState):
    text = state["alert"].lower()
    return {"safe": not any(p in text for p in SUSPICIOUS)}

def retrieve(state: AlertState):
    text = state["alert"].lower()
    hits = [v for k, v in THREAT_INTEL.items() if k in text]
    return {"context": hits}

def triage(state: AlertState):
    high = len(state["context"]) >= 1
    verdict = "High severity: matched known technique" if high else "Low severity: no match"
    return {"verdict": verdict, "needs_human": high}

def escalate(state: AlertState):
    return {"verdict": "Held: possible prompt injection", "needs_human": True}

def route(state: AlertState):
    return "retrieve" if state["safe"] else "escalate"

graph = StateGraph(AlertState)
graph.add_node("guard", guard)
graph.add_node("retrieve", retrieve)
graph.add_node("triage", triage)
graph.add_node("escalate", escalate)
graph.set_entry_point("guard")
graph.add_conditional_edges("guard", route)
graph.add_edge("retrieve", "triage")
graph.add_edge("triage", END)
graph.add_edge("escalate", END)
app = graph.compile()

result = app.invoke({"alert": "Encoded PowerShell command on host-17",
                     "safe": True, "context": [], "verdict": "", "needs_human": False})
print(result["verdict"], result["context"])
